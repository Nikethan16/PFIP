Non-negotiable design principles (the why behind every box)

  1. Trust through transparency. Every number cites its source. Every model's confidence is shown next to the prediction. The freshness dot on every KPI is the most-clicked widget.
  2. Honest about uncertainty. Empty states say why they're empty ("not yet ingested" vs "ingested but failing"). No fake numbers, no placeholder graphs.
  3. Privacy boundary is hard. Holdings + tax data never leave the machine via cloud LLMs. The router pins Sensitivity.PERSONAL prompts to local Ollama, period.
  4. No auto-execution, ever. v1 is paper-trading. The LLM produces recommendations the user evaluates. No broker integration places orders. This is architectural, not feature-flagged.
  5. The pre-commitment ladder is the safety belt. You cannot move from paper to 5% capital without 3 months of validated paper performance + a signed file + zero risk-rule breaches.
  6. Reproducibility. Every monetary write carries the FX rate used. Every model artifact carries its alembic_revision. Every backtest is seeded.
  7. Don't build for what hasn't happened. Failure-pattern clustering is heuristic until 50 closed entries exist. Trained model selector deferred until 12 months of labels exist.

1. Ingestion pipeline — runs in Prefect on cron per adapter

Trigger: per-adapter cron (e.g. 0 1 * * * for daily OHLCV, */15 * * * * for news) · Prefect flow: ingest_<source>_<cadence> in pfip/prefect/flows/

1

Compute idempotency key

pfip.ingest._common.idempotency.make_batch_key

  • SHA-256 of (source, symbol, start, end, timeframe, extra) with JSON-sorted extras
  • Stored on source_health.last_batch_key — second run with same key is a no-op
  • Survives retries, container restarts, manual re-triggers
2

Fetch — per-source adapter async

Each adapter is one async function with a uniform shape — never raises into the orchestrator

  • Crypto · ccxt (Coinbase / Kraken / Bybit / OKX) · public API, no key needed for OHLCV
  • US equity · yfinance + Stooq fallback · SEC EDGAR for fundamentals
  • Indian equity · jugaad-data + NSE/BSE bhavcopy
  • MFs · AMFI daily NAV CSV (authoritative)
  • FX · RBI reference rates primary · Frankfurter (ECB) fallback · 7-day business-day step-back
  • News · 10+ RSS feeds · GDELT · arXiv q-fin · Bluesky (atproto, no key)
  • On-chain · mempool.space (BTC) · Etherscan (ETH, key in .env)
  • Macro · FRED + DBnomics + World Bank + MOSPI
3

Validate — pandera schema check before insert

  • Column type + range checks (no negative volumes, no out-of-order timestamps, etc.)
  • Validation failures get logged + the batch is dropped rather than partially written
  • Schema-version pin recorded so we can detect contract drift later
4

Upsert — write to TimescaleDB hypertable

Single OHLCV hypertable indexed on (symbol, source, timeframe, ts)

  • Conflict resolution: latest write wins on the natural key — adapter that retries is safe
  • Hypertable chunks by ts (default 7 days) for fast time-range queries
  • FX-converted equivalents computed at write time via convert_to_inr when source ccy ≠ INR
5

Record health — source_health.record_run(source, rows, error=...)

  • One row per adapter · last_run_at, last_success_at, last_rows, consecutive_failures
  • Powers freshness dots on every KPI + the /health/sources endpoint + skipped-task watchdog
  • Tolerant of NULL error via SQL cast (fixed an early AmbiguousParameter bug)
6

Daily quality gates (post-ingest)

  • Reconcile · 18:45 UTC · cross-source close prices · flag pairs > 0.5% divergent · Telegram WARN
  • Anomaly scan · 00:00 IST · IsolationForest on (log_return, range_pct, gap_pct, volume_z) per symbol · WARN if ratio > 1% · writes JSONL to data/anomaly_log/<date>.jsonl
  • Skipped-task watchdog · hourly · reads Prefect deployments · WARN if any is > 2× its cadence budget

2. ML signal pipeline — runs nightly + on-demand

Trigger: regime-detect-btc-daily at 01:00 UTC · weekly retrainer train-lgbm-per-regime Sat 03:00 UTC · output: SignalRow with drivers + counter-arguments

1

Compute features — wide store keyed by (symbol, ts)

pfip/features/technicals.py · 150+ indicators via ta library

  • RSI / MACD / ATR / BB / Stochastics / etc. — RSI patched to saturate at 100/0 on pure trends (textbook; ta returns NaN otherwise)
  • Returns (1d / 7d / 30d, log + simple) · realized vol (10d / 30d / 90d)
  • Fundamentals ratios (P/E, P/B, D/E, ROE, ROIC, FCF yield) · None-safe on missing inputs
  • Derivatives features for crypto (funding-rate z-score, OI %change, squeeze-setup label) — public ccxt, no key
2

Regime detection — HMM per symbol

pfip/regime/hmm_detector.py · Gaussian HMM (hmmlearn) with quantile-band fallback

  • Fits on 3y trailing log-return series · 3 or 4 states (configurable)
  • States deterministically mapped to {bull_trend, bear_trend, sideways, high_volatility} by mean + std (highest-vol → HV, then min/max mean → bear/bull)
  • Written to regime table with since + confidence
  • Survivorship-aware: as_of_universe(rows, target_date) retains delisted-after-target symbols
3

Auto-selector — pick the right model for current regime

pfip/signals/auto_selector.py · hand-coded mapping until ≥ 12 months of labels exist for a trained selector

  • bull_trend → lgbm_trend_specialist
  • sideways → xgb_meanrev_specialist + ttm_short
  • high_volatility → catboost_riskoff at half size
  • accumulation / distribution → full ensemble
  • Manual override available via add_override(symbol, model_id)
4

Generate prediction — pinned model from the registry

File-backed registry at data/models/<id>/ · SHA-256 deduped uploads · pin_model(id, slot) sets the live artifact for (task, regime, horizon)

  • LGBMBaselineModel.predict_proba_up(X) → probability of forward up-move at horizon H
  • Confidence floor at 65 — below = HOLD (no signal row written)
  • BUY if P(up) > 0.65 · SELL if P(up) < 0.35 · else HOLD
5

Explain — per-prediction SHAP (or permutation fallback)

pfip/signals/explain.py · tries shap (lazy import), falls back to permutation importance

  • Top-5 signed drivers — positive = pushed prediction up, negative = pulled it down
  • Permutation fallback uses background-median substitution (deterministic, no extra deps)
  • Serialized to JSONB on signals.drivers
6

Attach news — top-5 supporting + top-3 opposing

pfip/signals/news_attach.py · joins on entity_tickers JSONB column populated by news pipeline

  • BUY supported by positive-sentiment news, SELL by negative, HOLD by neutral (|s| ≤ 0.2)
  • Ranked by (impact, |sentiment|, recency) over a 48h lookback
  • Counter-arguments surface the strongest opposite-side news
7

Persist — SignalRow with all of the above

  • Stored to signals table with confidence, regime, drivers (JSONB), counter_args, model_name, model_version
  • Surfaces on /signals + emits a Telegram alert (AlertKind.SIGNAL_FIRED) at the configured severity
  • Architectural rule: no signal row ever becomes an order automatically — user evaluates, journals, executes manually

3. Backtest + calibration pipeline — runs weekly + monthly

Backtest: backtest-walk-forward-btc-weekly Sat 02:00 UTC · Calibration: calibration_monthly first Sat 10:00 IST · RAGAS eval: monthly · output: tearsheets + ECE reports + Telegram WARN on regression

1

Load historical OHLCV — PIT-aware

pfip/backtest/walk_forward.py · uses survivorship-aware universe (as_of_universe) to avoid look-ahead

  • Loads the same wide features table the live signal uses — guarantees train/serve parity
  • Filters by as_of_date so retraining on FY-N can never see FY-N+1 data
2

Walk-forward · 3y / 21d / 5d

  • 3-year training window slides forward in 21-day steps
  • 5-day embargo between train + test prevents bar-leak from overlapping forward labels
  • One model per window saves the per-window OOS prediction set into backtest_runs
3

CPCV (López de Prado) — combinatorial purged CV

  • Builds 20 sets of (train, test) splits with purging + 5-day embargo
  • Robust to the autocorrelation that breaks standard k-fold on time series
  • Produces a path-distribution of Sharpe / Sortino / Calmar that exposes parameter sensitivity
4

Monte Carlo bootstrap — 1 000 block-bootstrap reorders

  • Tests whether the strategy's Sharpe is statistically distinguishable from a random reordering
  • Outputs p-value on Sharpe + confidence interval on terminal equity
  • Shuffle test for label-leakage detection runs alongside
5

Benchmarks + tearsheet

pfip/backtest/tearsheet.py · QuantStats fallback to built-in HTML

  • Benchmarks: buy-hold · MA 50/200 cross · RSI mean-reversion · risk-parity
  • Stats: Sharpe / Sortino / Calmar / max-DD / CAGR / hit-rate / monthly returns grid / underwater curve
  • Transaction-cost model applied per market (taker/maker spreads + impact)
6

Monthly calibration — Brier + ECE + reliability diagram

pfip/calibration/brier_ece.py · pulls realised labels from signals + ohlcv

  • Computes ECE per model-version over trailing 3 months
  • Auto-suspend rule: ECE > 0.15 for 2 consecutive months → emits suspend event into model_events
  • Persists per-model reliability bins to calibration_reports for the /calibration page
7

Monthly RAGAS eval — KB retrieval quality

pfip/kb/ragas_eval.py · 50-Q held-out set covering Wyckoff / Graham / Taleb / Tharp / Indian tax

  • Scores faithfulness + answer_relevancy + context_precision per question
  • Logs to MLflow + writes per-question CSV under data/.telemetry/ragas/
  • Regression guard: Telegram WARN if faithfulness < 0.70 or drops > 0.10 vs previous run

4. Chat agent pipeline — runs per user question over SSE

Trigger: POST /api/v1/chat/stream · Auth: JWT cookie · Returns: SSE stream of tokens + citation list + privacy badge

1

Classify intent — heuristic regex (no LLM call)

pfip/agent/intent.py · sub-ms · deterministic · 3 buckets

  • DB_QUERY — "how much BTC do I hold", "P&L yesterday", "list signals" → dispatch to tool registry
  • RAG_LOOKUP — "what does Wyckoff say about X", "news on RELIANCE" → vector retrieval
  • REASONING — "should I buy more ETH", "explain last signal" → full agent graph
  • Priority on tie: DB > RAG > REASONING · sub-2-word inputs fall back to REASONING
2

Tool-call (DB_QUERY branch) — typed registry

pfip/agent/tools.py · 5 tools · each safe-fails to {ok: false}

  • get_holdings(asset_class?) · get_current_price(symbol) · get_recent_pnl(days)
  • get_open_signals(limit) · get_tax_summary(fy)
  • Result is JSON-serialised and dropped into the LLM context as a structured tool-call response
3

RAG retrieval (RAG_LOOKUP branch) — Qdrant + citations

pfip/kb/search.py · two collections — kb (books) + news

  • Embeds query via current embedding model (Ollama nomic by default · NVIDIA NIM if keyed)
  • Top-5 chunks above cosine threshold (0.60 KB · 0.55 news)
  • Format citations: [Source: Wyckoff ch.4, p.87] prepended to each chunk before passing to LLM
4

Privacy classifier — choose the LLM destination

pfip/agent/privacy.py · Sensitivity enum drives routing in MultiProviderClient

  • PUBLIC — KB queries, market commentary → cloud (Groq → Gemini → DeepSeek → OpenRouter chain)
  • SENSITIVE — references the user's portfolio but indirectly → cloud OK if context-redacted
  • PERSONAL — holdings / tax / journal text → always local Ollama, full stop
  • Routing decision recorded in the SSE meta event so the UI can show the privacy badge
5

Synthesise + stream — via LiteLLM

pfip/agent/llm_client.py · MultiProviderClient over LiteLLM

  • Streams tokens via SSE — first token ~300 ms on cloud, ~1 s on local Ollama
  • Walks providers in priority order on failure (LLMAllProvidersFailed on full exhaustion)
  • Final fallback for PERSONAL prompts is local Ollama (llama3.1:8b-instruct)
6

Final SSE "done" event — citations + privacy badge

  • Citation list deduped by (book + chapter + page) or (news URL)
  • Privacy badge: PUBLIC / SENSITIVE / PERSONAL + actual provider hit (e.g. gemini-flash-lite or ollama-local)
  • Architectural rule: agent never produces typed signal rows — only conversational text. Signal generation is the ML pipeline's job.

5. Tax engine pipeline — on-demand + annual ITR drill

Trigger: GET /tax/summary, POST /tax/harvest, broker CSV upload via POST /tax/import/{broker} · annual drill: annual-itr-drill June 15 · output: STCG/LTCG/VDA summary · Schedule FA · Form 67 · ITR JSON · harvest plan

1

Ingest — 10 broker CSV adapters

pfip/brokers/csv_adapters/<broker>.py · Zerodha, ICICIdirect, Groww, INDmoney, Vested, WazirX, CoinDCX, Binance, Coinbase, Kraken

  • Each adapter normalises the broker's CSV into a uniform PortfolioTx shape: kind, symbol, qty, price, ccy, ts, fees, tds
  • Persisted to portfolio_tx table with broker column for audit
2

FX conversion — every tx tagged with INR equivalent

pfip/tax/fx_cost_basis.py · RBI primary, Frankfurter fallback, 7-day business-day step-back

  • Resolution order: DB (ohlcv where source='rbi') → Frankfurter API → 365-day static fallback
  • INR amount quantised to paise (2 decimals)
  • Rate stored alongside amount so reconstruction is exact (no rerunning years later)
3

Classify capital gains — FIFO lot matcher

pfip/tax/engine.py · classify_capital_gains(tx_rows) → list[CGEvent]

  • FIFO lot consumption per (symbol, asset_class)
  • 31-Jan-2018 grandfathering applied to equity LTCG (FMV substitution)
  • Holding-period bucketing per asset class: equity 365d, US stock 730d, debt 1095d, gold 1095d
  • VDA gains tagged separately — Section 115BBH rules apply (no offsetting, no carry-forward)
4

Compute summary — STCG / LTCG / VDA / dividend / interest

  • STCG equity @ 15% · LTCG equity @ 10% above ₹1 L exemption
  • VDA @ 30% flat + 1% TDS + no loss set-off (115BBH)
  • Debt MF post-2023 → slab rate
  • Dividend → slab + surcharge cliff check
  • Old vs new regime comparison + optimal regime recommendation
  • 80C / 80D / 80CCD(1B) optimizer ranks contributions by marginal tax saved
5

Loss harvesting — pfip/tax/harvest.py

Note: real bug found + fixed on 2026-05-30 — LTCG branch was subtracting the ₹1L exemption from harvested loss instead of taxable pool. Correct formula now: delta = taxable_before − taxable_after

  • Open lots in the red are scored by tax-saving potential against existing realised gains
  • VDA losses never suggested (Section 115BBH)
  • STCG equity loss matches STCG pool first, spills to LTCG (allowed)
  • LTCG savings honor the ₹1L exemption properly
  • Suggestions within 30 days of FY-end carry a re-buy warning chip
  • Surcharge-adjusted rates baked in
6

Forms — Schedule FA / Form 67 / Schedule CG / ITR JSON

  • Schedule FA · per-country peak USD balance + INR equivalent + dividends + proceeds (foreign assets)
  • Form 67 · DTAA Section 90 credit · min(foreign tax paid, Indian tax on same income)
  • ITR JSON · Schedule CG + Schedule FA in the income-tax portal's expected shape · CA handoff
  • Summary PDF · reportlab · all of the above on one page · disclaimer-stamped
7

Annual ITR drill — verify engine matches filed numbers

pfip/prefect/flows/annual_itr_drill.py · June 15 (advance-tax milestone)

  • Reads data/itr_filed/<FY>.json (user-supplied filed numbers) and recomputes via the engine
  • Tolerance ±2% on every aggregate line — out-of-band → Telegram WARN + markdown report under data/itr_calibration/
  • The reconciliation is the canonical "did this engine survive another year" test

6. Alerts pipeline — Telegram outbound with quiet hours + rate cap + escalation

Trigger: send_alert(kind, severity, ...) from any module · escalator: escalate-unacked Prefect flow every 30 min · output: Telegram message (or digest, or queued, or suppressed)

1

Render — markdown template per AlertKind

pfip/alerts/templates/<kind>.md · {key} substitutions filled from context dict

  • 12 alert kinds: morning_brief, regime_change, signal_fired, risk_breach, drawdown_halt, ingest_failure, calibration_breach, paper_trade_report, post_mortem_required, system_health, weekly_review, custom
  • Missing-key tolerance: template variable not in context → render raw (user sees the placeholder, no crash)
  • Title = first heading line · body = the rest
2

Severity routing — CRITICAL bypasses everything

  • CRITICAL · bypass quiet hours · bypass rate cap · bypass digest · always send · always escalate further
  • WARN · respect quiet hours · subject to rate cap · recorded into alerts:pending_ack for escalation
  • INFO · respect quiet hours · respect rate cap · digested (one-per-day batch flush)
3

Quiet-hours check — 23:00–07:00 IST

_is_quiet_hour(now_utc) · converts to IST + checks the window inclusive of start, exclusive of end

  • INFO + WARN suppressed → routed to digest queue
  • CRITICAL still fires
  • Kill-switch override: alerts:silenced=1 in Redis silences everything, including CRITICAL — manual unlock required
4

Rate cap — 10/hour via Redis sliding window

_check_rate_cap(redis) · sorted set keyed by timestamp · ZRANGEBYSCORE check

  • 10 successful sends per hour absolute · drops extras into digest queue rather than 429-ing
  • Cap is per-process — single-host install means it's effectively global
  • Reset by redis-cli DEL alerts:ratecap in incident response
5

Send — POST api.telegram.org

  • HTTP POST to /bot{TOKEN}/sendMessage with markdown formatting
  • disable_notification: true for INFO (silent on phone)
  • WARN payload recorded in alerts:pending_ack:<id> Redis hash for the escalator
  • Send failures (Telegram 429 / network) get logged + the alert is dropped — alert delivery never breaks the calling flow
6

Escalate — WARN → CRITICAL after 2 hours unack

escalate_unacked_warns() in dispatcher · driven by escalate-unacked Prefect flow every 30 min

  • Scans alerts:pending_ack:* keys · entries older than 120 min get re-sent as CRITICAL with "ESCALATED" prefix
  • ack_alert(id) clears a pending entry — wired to a Telegram inline-button callback (future enhancement)
  • Defence against: morning brief fails silently for 3 days, drawdown alert ignored, ingest stops returning data

Trade-offs the tech lead might probe

DecisionRationale
Local Ollama for PERSONAL sensitivity, not "best cloud model"Privacy boundary is more important than latency for tax / holdings queries · trade-off: ~5–10× slower first-token on those prompts
Heuristic intent classifier, not LLM-per-turnLatency · determinism · rules are short · LLM call has 200 ms minimum, regex is sub-ms · trade-off: occasional misclassification on edge phrasing (falls back to REASONING)
TimescaleDB (not a separate OHLCV store)One DB · same backup story · pgvector handles <10 M rows easily · single auth domain · trade-off: hot-path queries colocate with cold ones
File-backed model registry (not MLflow-as-primary)Registry is tiny · SHA-256 deduped · filesystem ops are fast · trade-off: pin state lives in a JSON manifest, not a "real" DB — fine for <1 K models
JSONL anomaly log (not a DB table)Append-only audit data · tail-greppable · no migration on day 1 · trade-off: can't JOIN anomalies to other data — but we don't need to yet
Prefect 2 (not Airflow)Better-than-Airflow for solo scale · great UI · per-deployment cron + retry · async-native · trade-off: smaller ecosystem of plugins than Airflow
Pre-commitment ladder (not "trust the human")The biggest losses come from skipping discipline gates · ladder gate is mechanical · cannot be overridden in the UI · trade-off: friction at advancement is the feature
Paper-trading only in v1 (no broker integration)Architectural — no API client that can call a broker · LLM can never trigger a trade · trade-off: every order is manual entry · feature, not bug
FIFO lot matching (not LIFO or "highest tax")Indian tax law mandates FIFO for equity · matches the broker's view · simplifies CA reconciliation · trade-off: occasionally not the tax-optimal sale (loss harvesting addresses this)
RAG eval monthly, not per-PREval is expensive · KB doesn't change often · trade-off: regression sits for up to a month — mitigated by faithfulness floor (0.70) being conservative
Slate & Teal palette (not pure dark Bloomberg)Modern institutional · not neon-trader · not consumer-y · matches "tool for engineers, not retail" persona · trade-off: requires both light + dark mode polish
Idempotent ingest keys via SHA-256Retries on container restart are common · double-writes corrupt aggregates · SHA is deterministic · trade-off: an extra Redis-ish check before every write

7. Persistence layer — what lives where

Three stateful stores · plus filesystem for artifacts & logs · plus Ollama local model weights

1

TimescaleDB · the source of truth for everything tabular

Postgres 16 + hypertables · 8 Alembic revisions · backup nightly via pg_dump → encrypted off-site

  • Time-series: ohlcv (hypertable), features, signals, regime, calibration_reports, news
  • Holdings: holdings, portfolio_tx, watchlist, journal
